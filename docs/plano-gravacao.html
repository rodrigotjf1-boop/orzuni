Plano de gravação dos vídeos

Orzuni · app.orzuni.com

Cada cenário é uma ação na interface — que vira uma requisição real à API. Marque o quadradinho ao concluir. Grave na ordem: os cenários finais reaproveitam itens dos primeiros.

Antes de gravar — checklist rápido

  • Login em app.orzuni.com feito.
  • Gravação em tela cheia, com data e hora do computador visíveis.
  • Informe o Client ID do app no chamado (junto com os links dos vídeos).
  • Nada de curl — o iFood cancela a análise. Sempre filme a tela do app.
  • Imagens de teste prontas na pasta docs/imagens-teste/ (JPG/PNG ≤ 5 MB).
A

Fundamentos e leitura

critério 1
A1 · Autenticação + listar catálogo
OAuth 2.0 · GET /catalogs · GET /items
  1. Abra o menu Cardápio. Os itens reais carregam vindos da API.
estar autenticado e ler o catálogo/itens existentes.
A2 · Criar categoria + item simples (com foto)
POST /categories · PUT /items · upload de imagem
  1. Cardápio → + Novo item.
  2. Em Foto → Escolher foto → selecione burger.png (mostre o preview e o aviso “JPG ou PNG · até 5 MB”).
  3. Nome “X-Salada”, descrição curta, Preço — digite os dígitos e veja a máscara formatar R$ 22,90.
  4. Em Categoria digite uma nova: “Lanches Teste”.
  5. Criar item → volte ao Cardápio e mostre o item na categoria nova.
criar categoria + item com título/descrição/preço/foto.
B

Complementos e estruturas especiais

critério 2
B1 · Item com complementos (≥ 2 grupos, min/max)
PUT /items com optionGroups
  1. + Novo item → nome/preço/categoria.
  2. Em Complementos → + Grupo “Ponto da carne” (mín 1 / máx 1): opções “Mal passado”, “Ao ponto”.
  3. + Grupo “Adicionais” (mín 0 / máx 3): “Bacon” R$ 4,00, “Cheddar” R$ 3,50.
  4. Criar → abra o item e mostre os dois grupos.
grupos de opções com preços e limites mín/máx.
B2 · Pizza — SIZE / CRUST / EDGE / TOPPING
type PIZZA · fractions · preço por tamanho
  1. Cardápio → + Pizza.
  2. Tamanhos: Pequena (4 fatias · máx 1 sabor · R$ 20), Média (8 · 2 · R$ 25), Grande (12 · 2 · R$ 32) — note a ilustração da pizza fatiada mudando com o nº de sabores.
  3. Massas: Tradicional (0), Fina (R$ 2). Bordas: Tradicional (0), Catupiry (R$ 3). Sabores: Calabresa, Margherita.
  4. Criar pizza → abra e mostre os 4 grupos.
estrutura de pizza com os 4 grupos obrigatórios.
B3 · Combo — grupo principal + modificador aninhado
type COMBO_V2 · MAIN · 3º nível
  1. Cardápio → + Combo.
  2. Grupo “Escolha o lanche” (marque principal, mín 1/máx 1): “X-Burger” R$ 15 — nele adicione customização “Ponto da carne” (especificação: Ao ponto/Bem passado) e “Retirar” (ingredientes: Sem alface); e “X-Bacon” R$ 18.
  3. Grupo “Bebida” (mín 1/máx 1): “Coca” R$ 8, “Guaraná” R$ 8.
  4. Criar combo → mostre a customização aninhada dentro do lanche.
combo com grupo principal e modificadores aninhados.
C

Operações do dia a dia

critério 3
C1 · Atualizar preço (reflete em ≤ 2 s)
Editor → Publicar
  1. Cardápio → clique no nome de um item (Editor) → mude o Preço (máscara R$) → Publicar. Mostre refletindo na hora e no Cardápio.
atualização de preço + sincronização ≤ 2 s.
C2 · Pausar / reativar item
status AVAILABLE/UNAVAILABLE
  1. Cardápio → Pausar um item → etiqueta “pausado” → Reativar.
atualização de status refletida no catálogo.
C3 · Preço em massa (1 chamada)
PATCH em lote
  1. Menu Preços → edite o preço de vários itens (contador “N pendentes”) → Publicar N preços.
atualização de preços de vários itens numa chamada.
C4 · Status em massa (1 chamada)
PATCH em lote
  1. Cardápio → marque as caixas de vários itens → “N selecionados” → Pausar selecionados → depois Reativar.
alternar disponibilidade em lote.
C5 · Contexto por canal (mecanismo)
contextModifiers
  1. Menu Preços → mostre o seletor de canal (Delivery / Cardápio Digital / Salão) e explique que os preços vão por canal. Ver ressalva.
preços/status por contexto (mecanismo — loja de teste é só Delivery).
C6 · Agendamento de disponibilidade (shifts)
PUT /items com shifts
  1. + Novo item (ou Editor) → Disponibilidade → + Janela de horário → dias seg–sex, 11:00–15:00 → Criar/Publicar → mostre salvo.
regras de disponibilidade por horário e dia.
D

Qualidade, validação e erros

critério 4
D1 · Validação de dados
título ≤100 · descrição ≤500 · preço > 0
  1. + Novo item → deixe o nome vazio e o preço em 0 → mostre a mensagem de erro (o app não envia inválido). Corrija e crie.
nenhum payload inválido enviado à API.
D2 · Tratamento de erro (CONFLICT)
mensagem clara, sem falha silenciosa
  1. Tente criar um item com um código de PDV já existente → mostre a mensagem de conflito.
erros específicos tratados com mensagem compreensível.
D3 · Multi-idioma + acentos
pt-BR · es-CO · en-US
  1. Crie itens: “Pão de Alho à Moda” (pt), “Empanada con Ají” (es), “Grilled Chicken” (en) → mostre os acentos corretos no Cardápio.
títulos em 3 idiomas e caracteres especiais.
D4 · Texto longo (50+ caracteres)
contador de caracteres
  1. Crie um item com nome/descrição > 50 caracteres → mostre o contador (…/100, …/500) e o item salvo.
itens com títulos/descrições longos.
