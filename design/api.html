Endpoints

Base https://api.orzuni.com/v1 · autenticação por Bearer da chave.
GET/cardapioitens + estado
# cardápio consolidado, já com estado no ar/pausado
curl https://api.orzuni.com/v1/cardapio \
  -H "Authorization: Bearer orz_live_..."
PATCH/precosreprecificar por PDV
# o ERP manda só o código de PDV — sem id do iFood
curl -X PATCH https://api.orzuni.com/v1/precos \
  -H "Authorization: Bearer orz_live_..." \
  -H "Idempotency-Key: a1b2c3" \
  -d '{ "itens": [{ "pdv": "cw4620855", "preco": 33.50 }] }'
PATCH/itens/{pdv}/statuspausar / reativar
# "acabou a mussarela" direto do PDV do cliente
curl -X PATCH https://api.orzuni.com/v1/itens/cw4620855/status \
  -H "Authorization: Bearer orz_live_..." \
  -d '{ "status": "pausado" }'
GET/alertasitens fora do ar
# o vigia como serviço: o que caiu e há quanto tempo
curl https://api.orzuni.com/v1/alertas \
  -H "Authorization: Bearer orz_live_..."
# → [{ pdv, nome, motivo:"cascata", desde:"2026-07-22T..." }]

Como o ERP conecta

1
Gere a chave

Uma chave por sistema, com escopo de leitura/escrita.

2
O ERP usa o código de PDV

Ele já tem o externalCode cadastrado no iFood — não precisa de id nenhum.

3
Orzuni traduz e publica

Vira PATCH /products/price no iFood, em lote, com idempotência.

4
Webhook de volta

O ERP é avisado de pausas e divergências em tempo real.
